# 大模型推理基础

## 一、softmax

logits原始分数转变成概率通过公式：

```python
def softmax(x):
    """计算softmax"""
    exp_x = np.exp(x - np.max(x))  # 减去最大值以防止数值溢出
    return exp_x / np.sum(exp_x)
```

## 二、温度temperature

**temperature 越低，模型越保守；**

因为温度低，比如小于1，分数/温度，相当于放大，即logits概率数组变得更加锐化，值与值的差距拉大，则输出高概率就越来越唯一，故保守。

**temperature 越高，模型越发散。**

因为温度高，比如大于1，分数/温度，相当于缩小，即logits概率数组变得更加平缓，值与值差距缩小，则输出不唯一，故发散

## 三、top_k_filter

只保留概率最高的 k 个 token，其他 token 概率设为 0。

## 四、top_p_filter

top_p_filter 会先将 token 按概率从高到低排序，然后从最高概率 token 开始累加，保留累计概率达到或刚超过 p 的最小 token 集合，其他 token 的概率设为 0，最后重新归一化。

## 五、INT8 量化理解

INT8 量化是将浮点数通过 scale_factor 映射到 -128 到 127 的整数范围内。  
量化公式可以理解为：

q = round(x / scale)

反量化公式为：

x_hat = q * scale

其中 q 是量化后的整数，x_hat 是反量化后的近似浮点数。

**scale_factor 决定了量化的精度和表示范围**。scale_factor 越小，能够表示的小数间隔越细，但整体表示范围越窄；scale_factor 越大，表示范围越大，但精度越粗。

当 value / scale_factor 超过 INT8 的表示范围时，会被 clip 到 -128 或 127，此时反量化误差会明显增大。

因此，量化的核心是在存储空间、数值范围和精度损失之间做权衡。

## 六、不同精度的存储大小

INT4，每一个参数占用0.5byte；INT8，每一个参数占用1byte

故对于7B参数的大模型，即70亿参数。

若使用4比特量化，则权重大约需要7x10^9X0.5byte=3.5X10^9byte，约等于3.5GB。

若使用48比特量化，则权重大约需要7x10^9X1byte=7X10^9byte，约等于7GB。

但只是**模型权重本身**，真实推理还会额外占用：**KV Cache，激活值，CUDA runtime buffer，框架开销，临时计算缓存。**

## 七、权重量化和激活量化

权重量化：把模型参数 weight 从 FP16/FP32 压缩成 INT8/INT4 等低精度格式。
主要目的是**减少模型权重占用的显存和存储空间**。

激活量化：把模型推理过程中产生的中间结果 activation 也转成低精度。
它不仅影响显存，还可能影响计算速度，但实现更复杂，因为激活值会随着输入动态变化。

## 八、pytorch推理理解

### 1.Tensor

Tensor 是 PyTorch 中的多维数组，是模型输入、模型参数和模型输出的基本数据结构。Tensor 具有 shape、dtype 和 device 三个重要属性。

**shape 表示张量形状，dtype 表示数据类型，device 表示张量位于 CPU 还是 GPU。**

其中，可以通过x.shape[0]获得第一维的大小，即batch size，**批量大小，一次输入到模型的数目**；

x.shape[1]获得第二维的大小，即sequence_length，**序列长度，样本数目**，token ID的数目。

### 2.to("cuda")

to("cuda") 用于将 Tensor 或模型参数移动到 GPU 显存中。推理时，模型和输入必须位于同一个 device，否则会出现 device mismatch 错误。

### 3.batch size

batch size 表示**一次输入模型的数据条数**。例如 shape 为 [2, 3] 的 Tensor，可以理解为 batch size 为 2，每条样本有 3 个特征。

在 LLM 推理中，输入形状通常可以理解为 [batch_size, sequence_length]。

### 4.model.eval()

model.eval() 用于将模型切换到推理模式。某些层在训练和推理时行为不同，例如 Dropout 和 BatchNorm，因此推理前通常需要调用 model.eval()。

**Dropout层，在训练模式会随机丢弃神经元，但是推理模式不会丢弃神经元。**

**BatchNorm层，在训练模式使用当前batch的均值和方差，在推理模式使用训练时累计的全局均值和方差。**

### 5.torch.no_grad()

torch.no_grad() 用于关闭梯度记录。推理阶段不需要反向传播，因此使用 no_grad 可以减少显存占用并提高推理效率。

### 6.最小推理流程

标准 PyTorch 推理流程是：

1. 创建或加载模型
2. 将模型移动到 GPU
3. 将输入 Tensor 移动到 GPU
4. 调用 model.eval()
5. 使用 with torch.no_grad()
6. 执行 output = model(input)


## 九、 抽样函数解读

```python
def sample_generate(model, input_ids, max_new_tokens, temperature=1.0, top_k=None):
    """
    使用 temperature + top_k + multinomial 采样生成。
    """
    model.eval()

    for step in range(max_new_tokens):
        with torch.no_grad():
            logits, _ = model(input_ids)

        # [B, vocab_size]
        logits = logits[:, -1, :]

        # temperature
        logits = logits / temperature

        # top_k 过滤
        if top_k is not None:
            v, _ = torch.topk(logits, min(top_k, logits.size(-1)))
            logits[logits < v[:, [-1]]] = -float("inf")

        # softmax 转概率
        probs = torch.softmax(logits, dim=-1)

        # 按概率采样
        next_token_id = torch.multinomial(probs, num_samples=1)

        # 拼回上下文
        input_ids = torch.cat([input_ids, next_token_id], dim=1)

    return input_ids
```

## 十、nanoGPT 源码阅读

### 1.sample_generate()

```python
@torch.no_grad()
def generate(self, idx, max_new_tokens, temperature=1.0, top_k=None):
    for _ in range(max_new_tokens):
        # if the sequence context is growing too long we must crop it at block_size
        idx_cond = idx if idx.size(1) <= self.config.block_size else idx[:, -self.config.block_size:]
        # forward the model to get the logits for the index in the sequence
        logits, _ = self(idx_cond)
        # pluck the logits at the final step and scale by desired temperature
        logits = logits[:, -1, :] / temperature
        # optionally crop the logits to only the top k options
        if top_k is not None:
            v, _ = torch.topk(logits, min(top_k, logits.size(-1)))
            logits[logits < v[:, [-1]]] = -float('Inf')
        # apply softmax to convert logits to (normalized) probabilities
        probs = F.softmax(logits, dim=-1)
        # sample from the distribution
        idx_next = torch.multinomial(probs, num_samples=1)
        # append sampled index to the running sequence and continue
        idx = torch.cat((idx, idx_next), dim=1)

    return idx
```

这是一个**自回归文本生成**函数，给定一个初始的 token 索引序列，逐步生成指定数量的新 token，每次生成一个并喂回模型。

```python
idx_cond = idx if idx.size(1) <= self.config.block_size else idx[:, -self.config.block_size:]
```

如果当前序列长度不超过 `block_size`，直接用全部序列；否则只保留**最后 `block_size` 个 token**，防止过长输入。为什么要保留最后block_size个token，相当于保留最近的上下文，通过最后的上下文去推理后面的token。

### 2.forward()

```python
def forward(self, idx, targets=None):
        device = idx.device
        b, t = idx.size()
        assert t <= self.config.block_size, f"Cannot forward sequence of length {t}, block size is only {self.config.block_size}"
        pos = torch.arange(0, t, dtype=torch.long, device=device) # shape (t)

        # forward the GPT model itself
        tok_emb = self.transformer.wte(idx) # token embeddings of shape (b, t, n_embd)
        pos_emb = self.transformer.wpe(pos) # position embeddings of shape (t, n_embd)
        x = self.transformer.drop(tok_emb + pos_emb)
        for block in self.transformer.h:
            x = block(x)
        x = self.transformer.ln_f(x)

        if targets is not None:
            # if we are given some desired targets also calculate the loss
            logits = self.lm_head(x)
            loss = F.cross_entropy(logits.view(-1, logits.size(-1)), targets.view(-1), ignore_index=-1)
        else:
            # inference-time mini-optimization: only forward the lm_head on the very last position
            logits = self.lm_head(x[:, [-1], :]) # note: using list [-1] to preserve the time dim
            loss = None

        return logits, loss
```

token embedding：把 token id 变成向量

tok_emb = self.transformer.wte(idx)

position embedding：把位置也变成向量

pos_emb = self.transformer.wpe(pos)

训练时：所有位置都算 logits，因为所有位置都要参与 loss。
推理时：只算最后一个位置 logits，因为只需要预测下一个 token。

## 十一、KV cache

### 1. Prefill

Prefill 是生成开始时处理完整 prompt 的阶段。模型会对完整输入序列做一次 forward，得到最后一个位置的 logits，并同时生成历史 token 对应的 Key/Value 缓存。

### 2. Decode

Decode 是自回归生成阶段。模型每次生成一个新 token，然后将新 token 拼接到上下文中继续生成。Decode 会重复很多次，因此是推理服务中的重要性能瓶颈。

### 3. KV Cache

KV Cache 是缓存 Transformer attention 中历史 token 的 Key 和 Value。没有 KV Cache 时，每生成一个新 token，都需要重新计算完整上下文的 attention 相关中间结果。

使用 KV Cache 后，prefill 阶段会缓存 prompt 的 K/V；decode 阶段每次只需要计算新 token 的 K/V，并复用历史 K/V。

### 4. 为什么 KV Cache 能加速

因为它避免了重复计算历史 token 的 Key 和 Value。生成越长，KV Cache 带来的加速越明显。

### 5. 为什么 KV Cache 会占显存

KV Cache 需要保存每一层、每个 attention head、每个历史 token 的 Key 和 Value。因此它的显存占用会随着以下因素增长：

- batch size
- sequence length
- layer 数量
- attention head 数量
- hidden size
- 数据类型，例如 FP16/BF16

因此长上下文和高并发请求会显著增加 KV Cache 显存压力。

### 6. 我的理解

KV Cache 是 LLM 推理系统中的核心机制。它用额外显存保存历史 token 的 Key/Value，换取 decode 阶段更少的重复计算。vLLM、SGLang 等推理框架之所以重要，很大一部分原因就是它们更高效地管理 KV Cache。

```python
# -*- coding: utf-8 -*-
import torch
from transformers import GPT2Config, GPT2LMHeadModel


def generate_without_cache(model, input_ids, max_new_tokens):
    print("\n=== without KV Cache ===")
    generated = input_ids

    for step in range(max_new_tokens):
        print(f"step {step+1}: model input shape = {generated.shape}")

        with torch.no_grad():
            outputs = model(generated, use_cache=False)

        logits = outputs.logits
        next_token_logits = logits[:, -1, :]
        next_token_id = torch.argmax(next_token_logits, dim=-1, keepdim=True)

        generated = torch.cat([generated, next_token_id], dim=1)

    return generated


def generate_with_cache(model, input_ids, max_new_tokens):
    print("\n=== with KV Cache ===")

    generated = input_ids
    past_key_values = None

    for step in range(max_new_tokens):
        print(f"step {step+1}: model input shape = {input_ids.shape}")

        with torch.no_grad():
            outputs = model(
                input_ids,
                use_cache=True,
                past_key_values=past_key_values,
            )

        logits = outputs.logits
        past_key_values = outputs.past_key_values

        print("type of past_key_values:", type(past_key_values))
        print("number of layers in past_key_values:", len(past_key_values))

        for layer_idx, layer_cache in enumerate(past_key_values):
            print(f"\nlayer {layer_idx}:")
            print("type of layer_cache:", type(layer_cache))
            print("len of layer_cache:", len(layer_cache))

            for item_idx, item in enumerate(layer_cache):
                if hasattr(item, "shape"):
                    print(f"  item {item_idx} shape:", item.shape)
                else:
                    print(f"  item {item_idx} type:", type(item))

        next_token_logits = logits[:, -1, :]
        next_token_id = torch.argmax(next_token_logits, dim=-1, keepdim=True)

        generated = torch.cat([generated, next_token_id], dim=1)

        # 关键：下一步只输入最新生成的 token
        input_ids = next_token_id

    return generated


def main():
    device = "cuda" if torch.cuda.is_available() else "cpu"
    print("device:", device)

    config = GPT2Config(
        vocab_size=20,
        n_positions=32,
        n_embd=32,
        n_layer=2,
        n_head=4,
    )

    model = GPT2LMHeadModel(config).to(device)
    model.eval()

    input_ids = torch.tensor([[1, 5, 8, 3]], device=device)

    print("initial input_ids:", input_ids)
    print("initial shape:", input_ids.shape)

    out1 = generate_without_cache(model, input_ids.clone(), max_new_tokens=5)
    out2 = generate_with_cache(model, input_ids.clone(), max_new_tokens=5)

    print("\nwithout cache output:", out1)
    print("with cache output:", out2)


if __name__ == "__main__":
    main()
```

### 7.KV Cache shape 实验

本实验中，小 GPT2 模型配置为：

- n_layer = 2
- n_head = 4
- n_embd = 32
- head_dim = n_embd / n_head = 8

运行 with KV Cache 后，past_key_values 的类型为 DynamicCache，长度为 2，说明每一层 Transformer 都有一份 KV Cache。

运行部分结果展示：

```
type of past_key_values: <class 'transformers.cache_utils.DynamicCache'>
number of layers in past_key_values: 2

layer 0:
type of layer_cache: <class 'tuple'>
len of layer_cache: 3
  item 0 shape: torch.Size([1, 4, 4, 8])
  item 1 shape: torch.Size([1, 4, 4, 8])
  item 2 type: <class 'NoneType'>

layer 1:
type of layer_cache: <class 'tuple'>
len of layer_cache: 3
  item 0 shape: torch.Size([1, 4, 4, 8])
  item 1 shape: torch.Size([1, 4, 4, 8])
  item 2 type: <class 'NoneType'>
```

每层 layer_cache 的前两个元素分别是 **key cache 和 value cache**，其 shape 为：

[batch_size, num_heads, sequence_length, head_dim]

在本实验中，第一步输入 prompt `[1, 5, 8, 3]`，所以 sequence_length = 4，key/value shape 为：

```
key shape:   [1, 4, 4, 8]
value shape: [1, 4, 4, 8]
```

含义是：

```
1 = batch size
4 = attention head 数量
4 = 当前缓存的 token 长度，随自回归增长
8 = 每个 head 的维度 head_dim
```

后续 decode 阶段每次只输入 1 个新 token，但 KV Cache 中保存的 sequence_length 会不断增长：

step 1: [1, 4, 4, 8]  
step 2: [1, 4, 5, 8]  
step 3: [1, 4, 6, 8]  
step 4: [1, 4, 7, 8]  
step 5: [1, 4, 8, 8]

这说明 KV Cache 通过保存历史 token 的 Key/Value，避免了重复计算历史上下文。但它也会随着上下文长度增加而占用更多显存。

实验中，with cache 和 without cache 的最终输出一致，说明 KV Cache 不改变生成结果，只改变计算方式。

### 8.模型配置理解

首先，输入token id: input_ids = [[1, 5, 8, 3]]

**对于n_embd = 32**

表示每个 token 在模型内部会被表示成一个 32 维向量。

即：token 1 → [0.12, -0.05, 0.33, ..., 0.08]  共 32 个数

故**hidden size**表示模型内部每个 token 用多少个数字。

**对于n_head = 4**

代表attention head = 4

模型用四个attention去关注上下文关系。

**对于head_dim = n_embd / n_head = 8**

代表每一个head的维度为8

### 9.Q,K,V的理解

在 attention 里，每个 token 会生成 3 类向量：

```
Q = Query
K = Key
V = Value
```

```
Query：当前 token 想找什么信息
Key：每个历史 token 提供的“索引/标签”
Value：每个历史 token 真正携带的信息内容
```

### 10.kv cache的显存估算

KV Cache 显存 =2 × n_layer × batch_size × seq_len × hidden_size × bytes_per_element

2代表每一层都缓存两份，一个是key cache，另一个是value cache

以本实验的小 GPT2 为例：

n_layer = 2  
batch_size = 1  
seq_len = 8  
hidden_size = 32  
FP32 = 4 bytes  

因此：

2 × 2 × 1 × 8 × 32 × 4 = 4096 bytes ≈ 4 KB

对于一个 7B-like 模型，假设：

n_layer = 32  
hidden_size = 4096  
seq_len = 4096  
batch_size = 1  
FP16 = 2 bytes  

则 KV Cache 约为：

2 × 32 × 1 × 4096 × 4096 × 2 bytes
≈ 2.0 GiB

这说明，即使 batch size 为 1，长上下文下 KV Cache 也会占用大量显存。随着 batch size 和 seq_len 增加，KV Cache 显存会线性增长。
