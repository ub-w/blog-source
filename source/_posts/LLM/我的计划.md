# 我的计划

------

## 阶段 1：补完 LLM 推理引擎核心机制

你已经完成：

```
softmax / sampling
temperature / top-k / top-p
自回归生成
PyTorch forward
KV Cache
KV Cache 显存估算
Sequence / BlockManager 入门
```

还需要完成：

```
1. nano-vLLM 的 BlockManager：allocate / may_append / deallocate
2. prefix cache：相同前缀如何复用 block
3. scheduler：waiting/running 请求如何调度
4. prefill/decode：多个请求如何组织 batch
```

这部分不用学所有代码，只学机制。

完成标准：

```
你能画出 vLLM 请求生命周期：
request → token_ids → Sequence → scheduler → KV block allocation → prefill → decode → release
```

------

## 阶段 2：真正跑 vLLM 服务

学完 nano-vLLM 不能停在 notebook，必须跑真实服务。

你要做：

```
pip install vllm
vllm serve <一个小模型> --host 0.0.0.0 --port 8000
```

然后用 Python 调用 OpenAI-compatible API。

你要理解这些参数：

```
--max-model-len
--gpu-memory-utilization
--max-num-seqs
--max-num-batched-tokens
--tensor-parallel-size
--kv-cache-dtype
```

这些参数是真实生产里会调的。vLLM 官方优化文档也明确把 `gpu_memory_utilization`、`max_num_seqs`、`max_num_batched_tokens`、tensor/pipeline parallel size 和 KV cache 空间联系起来。

## 阶段 3：做一个能写简历的推理服务项目

项目名可以叫：

```
llm-inference-lab
```

功能：

```
1. FastAPI 封装 /chat
2. 后端支持 Ollama / vLLM 两种模式
3. 支持 temperature/top_p/max_tokens
4. 记录 TTFT、总延迟、输出 token 数
5. 写 benchmark.py 并发压测
6. 记录 nvidia-smi 显存变化
7. README 写清楚实验结果
```

这时你的简历就不是“看过 nano-vLLM”，而是：

```
基于 vLLM 构建 LLM 推理服务，支持 OpenAI-compatible API 接入；实现并发压测脚本，分析不同上下文长度、并发数和采样参数对 TTFT、吞吐量和 KV Cache 显存占用的影响。
```

这才有就业价值。
